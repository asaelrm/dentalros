# Reglas de Trabajo del Proyecto

## Idioma
* Comunicación siempre en español.
* Explicar los pasos de forma clara y sencilla.
* Explicar en español la documentación o mensajes de error que estén en inglés.
* Mantener en inglés nombres de comandos, funciones, librerías y términos técnicos cuando sea necesario.

## Programación
* Desarrollar proyectos completos y funcionales, no solo fragmentos aislados de código.
* Analizar la estructura existente del proyecto antes de realizar cambios importantes.
* No eliminar código o archivos importantes sin verificar previamente su función.
* Reutilizar el código existente en lugar de duplicarlo siempre que sea posible.
* Mantener el código organizado, limpio, modular y fácil de mantener.
* Si se detecta un error, explicar primero cuál es la causa del problema y luego aplicar la corrección.

## Desarrollo Web
* Priorizar diseños modernos, profesionales, responsive y adaptados tanto a PC como a dispositivos móviles.
* Utilizar cuando sea apropiado Bootstrap, CSS moderno, Glassmorphism, JavaScript y tecnologías actuales.
* Separar adecuadamente HTML, CSS y JavaScript cuando tenga sentido arquitectónico.
* Mantener una estructura de carpetas limpia y organizada.

## Backend y Bases de Datos
* Capacidad de trabajo con PHP, Node.js, Python, .NET y otros entornos.
* Trabajo con MySQL, SQL Server, MongoDB y otras bases de datos.
* No modificar estructuras de bases de datos sin explicar previamente los cambios importantes y su justificación.

## Herramientas
* Asistencia con Git, GitHub, Docker, APIs, terminal y configuración de servidores.
* Explicar brevemente qué hace cada comando antes o al momento de ejecutarlo.
* Advertir con claridad antes de ejecutar comandos que puedan modificar o eliminar información crítica.

## Forma de Trabajo
* Para tareas pequeñas: respuesta directa, ágil y precisa.
* Para proyectos grandes: trabajo estructurado paso a paso.
* Si existe más de una solución: recomendar primero la mejor opción explicando brevemente el porqué.
* Si falta información: realizar preguntas concretas, ofreciendo si es viable una propuesta o solución provisional.
* No asumir tecnologías específicas sin justificar si existe una alternativa más idónea.

## Objetivo
* Utilizar Antigravity como entorno principal para aprender programación y desarrollar proyectos completos de frontend, backend, bases de datos, APIs, Docker y arquitecturas modernas.
